## 一、系统定位（一句话）

**通过自动化营销系统，全盘管控「营销活动 + 临时活动」从日历排期 → 方案 → 待办 → 上线准备 → 监控 → 复盘 → 归档的全流程；每个节点有字段、负责人、截止时间、验收标准、确认记录；AI 辅助但不自动上线。**

### 1.1 系统不是什么

| ❌ 不是 | ✅ 是 |
| --- | --- |
| 辅助写方案的 Word 工具 | 营销活动的**唯一管控中枢** |
| 自动上线机器人 | **人机协作**：AI 生成 + 运营师确认 |
| 仅覆盖计划内 Banner 活动 | **国内+海外（明年）+ 临时活动 + AI 创意** 全覆盖 |

### 1.2 三类数据来源

| 来源 | 输入物 | 系统入口 |
| --- | --- | --- |
| **飞书营销日历 / Excel** | 全年规划方向 | Agent1 · ⑤ 方案库（同步后待审） |
| **行业情报 + LLM** | 报告、竞对、趋势 | 行业情报中心 → AI 建议 → ⑤ 方案库 |
| **数仓 MCP** | 客户行为、漏斗、订单 | Agent2 圈客 / Agent3 监控 / Agent4 复盘 |

### 1.3 三类归档资产（闭环）

| 资产库 | 内容 | 回流用途 |
| --- | --- | --- |
| **活动案例库** | 活动总结报告、成败标签 | Agent1 策划 RAG |
| **客户画像库** | 本次活动有产 client 清单 | 下次圈客参考 |
| **活动高产酒店库** | 高产 hotel + 活动标签 | 下次选品参考 |

## 四、运营视角：首页五池 + Agent1 漏斗

### 4.1 首页五池（互斥统计）

| 池 | 含义 | 对应流程段 |
| --- | --- | --- |
| **⑤ 方案库待审** | 飞书/AI/临时活动，未采纳 | ① 入口 |
| **① 全年计划池** | 已采纳、确定要上的活动 | ② 完成后 |
| **② 需立即准备** | ① 的子集：3 个月内、未上线 | ③④ 进行中 |
| **③ 准备完毕待上线** | Agent2 完成 + 等上线日 | ④ 完成 |
| **④ 执行中** | 已 live，Agent3 监控 | ⑤ |

### 4.2 Agent1 漏斗 UI 顺序

```
⑤ 方案库（飞书 + AI + 临时）
        ↓ 确认采纳
① 全年活动计划池
        ↓ 按时间推进
② 需立即准备 → ③ 待上线 → ④ 执行中
```

## 六、状态机（活动生命周期）

```
draft
  → plan_review          [Agent1 方案评审]
  → sent_to_agent2       [G3 送 Agent2]
  → resource_config      [Agent2 圈客选品]
  → todo_execution       [③ 待办执行]
  → testing              [待办验收 + 测试]
  → launch_prep          [④ 上线准备 Checklist]  ← 新增状态
  → scheduled            [排期等上线日]
  → live                 [⑤ 正式上线]
  → monitoring           [Agent3 监控]
  → review               [⑥ 复盘]
  → archived             [⑦ 三库归档]
```

## 十一、设计原则（开发时遵守）

1. **先 SOP 后 Schema**：业务字段定稿再落库，避免反复改
2. **AI 不自动上线**：每个关键节点必须有人工闸门记录
3. **一条活动一条流水线**：所有状态、待办、确认可追溯
4. **三库闭环**：归档不只是报告，客户和酒店要独立成库
5. **最小改动**：5-Agent 架构不动，在现有模块上加深

## 十三、8/18 会议纪要补充（SOP 规则 · 分工 · 分期）

### 13.1 营销日历规划规则

| 规则 | 系统设计要求 |
| --- | --- |
| **覆盖范围** | 当前：国内线下活动；**明年新增海外板块** + **临时活动专属入口** |
| **六大规划维度** | 年度离店数据、提前预定周期、目的地淡旺季、节假日、竞品活动、季节属性 → 写入日历搭建参考面板 / AI 校验输入 |
| **AI 校验机制** | 初版日历完成后：AI 基于公开数据 + 内部 OP 报告 → 排查冲突/频次 → 补充增量目的地提醒 → **进 ⑤ 方案库待审** |
| **定稿协同** | AI 校验通过 → **营销负责人审核定稿** → 全公司宣发（资源/营销/业务组）→ 非特殊情况**不得随意新增临时活动** |

**Agent1 新增能力**：
- `calendar_build_assistant`：六维度数据聚合 + AI 冲突/频次校验
- `calendar_finalize_gate`：营销负责人定稿闸门（G0.5）
- 临时活动入口：受控创建（需说明特殊原因）

### 13.2 活动立项与建档规则

| 规则 | 系统设计要求 |
| --- | --- |
| **自动建档** | 日历定稿 → 自动立项 → 按活动类型匹配准备周期 → 生成活动主线 + 任务流 → **自动节点催办** |
| **三类核心表格** | ① 营销规划主表 ② 全量活动+步骤明细表 ③ 目的地资源规划表 → 对应三个数据视图/导出 |
| **任务池机制** | 系统自动生成待办池，提前推送即将启动节点 + 负责人，**无需人工录入全量任务** |

**数据模型**：
```
dim_campaign          ← 营销规划主表（活动级）
fact_activity_todos   ← 活动+步骤明细（任务级，六要素）
dim_destination_resource_plan  ← 目的地资源规划表（Rachel 规则驱动）
fact_node_reminders   ← 节点催办（按准备周期自动触发）
```

**准备周期规则**（按活动类型 + 目的地）：
