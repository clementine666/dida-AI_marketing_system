## 一、核心定位（会议共识）

**通过自动化营销系统，全盘管控所有营销活动（营销活动 + 临时活动）的全流程。**

系统不是「辅助写方案的工具」，而是**从计划到归档的唯一管控中枢**——每个活动在每个节点上的状态、待办、负责人、交付物、验收标准，都应在系统内可追溯。

### 1.1 全流程七段

```
① 营销日历计划排期管理
        ↓
② 每个活动/临时活动的方案梳理（结构化模块）
        ↓
③ 方案涉及的模块待办事项管理
   （什么模块 · 什么内容 · 做什么事 · 谁做 · 何时完成 · 交付验收 · 确认）
        ↓
④ 上线准备（多维度确认清单）
        ↓
⑤ 正式上线和监控
        ↓
⑥ 复盘下结论
        ↓
⑦ 归档入库（三类资产沉淀）
```

---

### 1.2 ③ 待办事项管理 — 六要素

| 要素 | 说明 |
| --- | --- |
| **什么模块** | 方案中的哪个模块（如圈客、选品、Banner、券配置） |
| **什么内容** | 该模块要产出什么（名单、素材、配置项） |
| **要做什么事** | 具体动作（对接资源方、制作海报、配置优惠券） |
| **谁去做** | 负责人 / 协作方（运营师、资源方、设计、技术） |
| **什么时候完成** | 计划完成时间 / 里程碑 |
| **交付验收 · 确认** | 交付物标准 + 验收人 + 确认记录 |

---

### 1.3 ④ 上线准备 — 确认清单

上线前需逐项确认（不可跳过）：

| 确认项 | 说明 |
| --- | --- |
| **位置确认** | 首页 Banner / 二级 Banner / 其他营销广告位 |
| **图片海报确认** | 素材规格、文案、视觉验收 |
| **目标确认** | 量化目标、成功标准 |
| **资源确认** | 酒店资源画像、数量、交付状态 |
| **客户群确认** | 圈客逻辑、名单、规模 |
| **优惠券配置** | 券规则、面额、适用范围 |
| **上下线时间设定** | 上线日、下线日、预热期 |
| **过程数据字段确认** | 埋点、漏斗指标、看板所需字段 |
| **看板呈现形式确认** | 监控看板布局、维度、刷新频率 |
| **目标达成计算方式确认** | 如何判断成功/失败、ROI 口径 |

---

### 1.4 ⑦ 归档入库 — 三类资产

| 归档物 | 入库目标 | 用途 |
| --- | --- | --- |
| **活动总结报告** | 案例库 | Agent1 下次策划 RAG 参考 |
| **有产客户清单** | 客户画像库 | 高价值客户标签、下次圈客参考 |
| **高产酒店清单 + 活动标签** | 活动高产酒店库 | 爆款酒店沉淀、选品参考 |

> 注：会议明确「高产酒店库」与「客户画像库」是**独立资产库**，不只是复盘报告里的附件。

## 二、与现有 5-Agent 系统对照

| 会议七段 | 现有系统 | 覆盖度 | 主要缺口 |
| --- | --- | --- | --- |
| ① 日历排期 | Agent1 · 飞书同步 + ⑤方案库 + ①计划池 | 🟡 部分 | 缺「临时活动」独立类型；日历表头字段未对齐 |
| ② 方案梳理 | Agent1 · Schema v2 十一模块 | 🟡 部分 | 缺活动类型、位置形式、验收标准、模块推进机制 |
| ③ 待办管理 | Agent2 · 待办清单 | 🟡 部分 | 缺六要素结构化（负责人/交付/验收/时间） |
| ④ 上线准备 | Agent2 · testing → scheduled | 🔴 不足 | 上线准备 10 项确认清单未系统化 |
| ⑤ 上线监控 | Agent3 · 看板 | 🟡 部分 | 看板字段/呈现/告警待对齐曼薇 |
| ⑥ 复盘 | Agent4 · 复盘报告 | 🟡 部分 | 复盘维度、提醒、输出格式待定义 |
| ⑦ 归档 | Agent5 · 案例库 | 🔴 不足 | 缺客户画像库、高产酒店库、活动标签 |

**结论**：框架方向认可，下一步是**按真实业务把每个节点的字段、流程、验收标准拆细**。

## 五、建议推进顺序

```
Week 1  A（日历表头）+ B（方案 SOP）     ← 基础契约，AI/Agent 都依赖
Week 2  C（AI 提示词）+ D（监控字段）    ← 对齐曼薇/JIM 的数据需求
Week 3  E（复盘机制）+ F（全流程验证）   ← 用真实活动走通一条
Week 4  G（部署）+ 改造 Backlog 排期     ← 根据 A~F 输出更新系统
```

**原则**：先定「业务 SOP 和字段标准」（A/B/D/E），再改系统；避免系统字段与业务口径反复对不齐。
