## 一、系统定位与价值

### 1.1 一句话定位

> 💡 **核心定位**  
> 把「飞书营销规划 + 数仓客户行为 + 行业情报」变成：  
> **可评审的活动方案 → 可执行的圈客选品 → 可监控的上线活动 → 可复用的历史档案。**

> ⚠️ **核心原则**  
> **每个关键节点由运营师确认，AI 不自动上线。**

---

### 1.2 解决什么问题

| 现状痛点 | 系统价值 |
| --- | --- |
| 飞书日历只有规划方向，没有完整方案 | Agent1 补全背景、目标、客群、交付方式 |
| 圈客选品靠人工查数、效率低 | Agent2 调 MCP 实时圈 client / 选 hotel |
| 上线后监控分散、复盘滞后 | Agent3 盯漏斗，Agent4 出复盘 |
| 经验散落在个人 | Agent5 归档，Agent1 下次策划可引用 |

---

### 1.3 三类数据来源

| 来源 | 用途 | 谁用 |
| --- | --- | --- |
| **飞书营销日历 / Excel** | 全年规划方向 | Agent1（先进方案库，采纳后进计划池） |
| **数仓 MCP** | 客户行为、漏斗、订单 | Agent2 / Agent3 / Agent4 |
| **行业情报 + LLM** | AI 活动建议 | Agent1 方案库 |

## 二、全链路工作逻辑

### 2.1 首页五池（运营视角）

**漏斗顺序（Agent1 工作台与首页一致）：**

```
⑤ 方案库待审
  ├ 飞书营销规划
  └ AI 行业建议
        ↓  运营师：评审 + 补充 + 「确认采纳 · 进入全年计划池」
① 全年活动计划池（确定要上的活动）
        ↓  按推广时间推进
② 需立即准备（3 个月内、未上线、还在做方案/圈客）
        ↓
③ 准备完毕待上线（Agent2 配完，等上线日）
        ↓
④ 执行中（已上线，Agent3 监控）
        ↓
已结束 → 复盘 → 归档
```

> 📋 **说明**  
> - **②③④ 互斥**：同一活动同一时间只在一个池里  
> - **① 包含全年已采纳活动**：含执行中、已结束（首页统计仍计入，界面可灰显）  
> - **⑤ 不含已拒绝项**：拒绝后移出待审，记录保留

---

### 2.2 五 Agent 流水线

```
Agent1 方案策划
      ↓
Agent2 资源配置
      ↓
Agent3 活动监控
      ↓
Agent4 活动分析
      ↓
Agent5 活动归档
      ↓（历史经验回流）
Agent1 方案策划
```

### 2.3 活动状态机（系统在跟什么）

  → testing

## 三、分 Agent 说明（职责 + 流程 + 运营操作）

---

### Agent1 · 方案策划师

**定位**

全年活动策划中心：读日历、收情报、出结构化方案。

**不做**：圈客、配 Banner、监控、复盘。

**工作流程**

```
同步飞书 / Excel → 进 ⑤ 方案库
行业情报 + LLM → AI 建议进 ⑤
运营师评审补充 → 确认采纳 → 进 ① 全年计划池
识别 ② 需立即准备的活动 → 完善方案 → 送 Agent2
```

**运营师操作**

| 步骤 | 操作 | 在哪 |
| --- | --- | --- |
| 1 | 看 ⑤ 待审列表（首页点卡片或进 Agent1） | 系统首页 / Agent1 |
| 2 | 飞书规划：「评审并采纳」或「拒绝」 | Agent1 · ⑤ 方案库 |
| 3 | AI 建议：「评审方案」→ 采纳 / 拒绝 | Agent1 · ⑤ 方案库 |
| 4 | 在评审页编辑 11 模块方案（背景、目标、客群、Query Profile 等） | 活动方案评审页 |
| 5 | 「确认采纳 · 进入全年计划池」 | 评审页 |
| 6 | 「送 Agent2」 | ① 全年计划池列表 |

**运营师必须确认**

| 确认项 | 说明 |
| --- | --- |
| ✅ 方案库条目采纳 / 拒绝 | 飞书规划、AI 建议要不要做 |
| ✅ 结构化方案内容 | 背景、目标、客群、交付方式等 |
| ✅ Query Profile（⑥⑦） | 目的地、分组 ID、时间窗、星级等（Agent2 圈客契约） |
| ✅ 确认采纳进全年计划池 | 不确认不能送 Agent2 |
| ✅ 送 Agent2 | 主动推送，系统不会自动送 |

---

### Agent2 · 客户资源配置师

**定位**

把 Agent1 已确认方案变成：**client 清单 + hotel 清单 + 上线待办**。

**不做**：改活动主题、改方案目标、自动上线。

**工作流程**

```
读 Agent1 的 Query Profile
  → 调 MCP 圈客选品
  → 运营师验收结果
       ├ 改条件 → 重新查 MCP
       ├ 仍不对 → 手工补 client_id / hotel_id
       └ 满意 → 锁定资源配置 → 生成待办
  → 待办逐项完成 → 提交测试 → 排期上线
```

**运营师操作**

| 步骤 | 操作 |
| --- | --- |
| 1 | 在 Agent2 打开活动，看圈客 / 选品结果 |
| 2 | 不满意：改 Query 条件 →「预览 MCP 查询」→ 再执行 |
| 3 | 仍不满意：上传 / 覆盖 client_id、hotel_id |
| 4 | 满意：「确认锁定资源配置」→ 生成待办 |
| 5 | 逐项完成待办（Banner、券、短信、埋点等） |
| 6 | 「提交测试」→ 测试通过后进入待上线 |

**运营师必须确认**

| 确认项 | 说明 |
| --- | --- |
| ✅ 圈客结果 | 客户分组、数量、名单是否合理 |
| ✅ 选品结果 | 酒店 ID、星级、价格竞争力 |
| ✅ Query 条件变更 | 改条件后重新确认 |
| ✅ 人工 ID 覆盖 | 战略客户 / 酒店手工补入 |
| ✅ **锁定资源配置** | 锁定后才生成待办，不可跳过 |
| ✅ 待办全部完成 | 未完成不能提交测试 |
| ✅ 提交测试 / 测试通过 | 进入 scheduled 待上线 |

---

### Agent3 · 活动监控师

**定位**

活动上线后**只看数据、发告警**，不改圈客和 Banner。

**不做**：改方案、改资源配置。

**工作流程**

```
活动 live → 生成监控看板预览
  → 运营师确认监控生效
  → 按 Agent1 目标 + Agent2 埋点配置盯漏斗
  → 超阈值告警（规划中）
```

**运营师操作**

| 步骤 | 操作 |
| --- | --- |
| 1 | 活动上线后进 Agent3 |
| 2 | 预览看板（Banner CTR → RP → 订单 / TTV） |
| 3 | 确认监控配置生效 |
| 4 | 收到告警后决策：调方案 or 调资源（人工决策，系统只提示） |

**运营师必须确认**

| 确认项 | 说明 |
| --- | --- |
| ✅ 监控看板 / 规则确认 | 正式进入 monitoring 状态 |
| ⚠️ 告警响应 | 目前偏框架，告警渠道待完善 |

---

### Agent4 · 活动分析师

**定位**

活动结束后**复盘**：目标 vs 实际、漏斗、ROI、问题建议。

**不做**：活动中改配置。

**工作流程**

```
活动结束 → 拉全链快照 + 数仓实际数据
  → 生成复盘报告
  → 运营师验收
  → （规划）回写飞书复盘表
  → 送 Agent5 归档
```

**运营师操作**

| 步骤 | 操作 |
| --- | --- |
| 1 | 活动进入 review 后进 Agent4 |
| 2 | 查看复盘报告 |
| 3 | 补充 / 修改结论 |
| 4 | 「验收复盘」确认 |

**运营师必须确认**

| 确认项 | 说明 |
| --- | --- |
| ✅ 复盘报告验收 | 不验收不进归档 |
| ⚠️ 飞书回写字段 | 规划中 |

---

### Agent5 · 活动归档师

**定位**

把复盘结论结构化进**活动案例库**，供 Agent1 下次策划 RAG 参考。

**不做**：改进行中活动。

**工作流程**

```
Agent4 验收通过 → 结构化归档
  → 写入案例库（可检索目的地、类型、成败标签）
  → Agent1 策划时自动引用
```

**运营师操作**

| 步骤 | 操作 |
| --- | --- |
| 1 | 在 Agent5 查看待归档活动 |
| 2 | 确认归档标签、可复用经验、避坑点 |
| 3 | 确认归档入库 |

**运营师必须确认**

| 确认项 | 说明 |
| --- | --- |
| ✅ 归档确认 | 案例才进入库供后续引用 |

## 七、会议 Q&A 参考

**Q：飞书规划同步进来就算采纳了吗？**  
A：不算。同步后先进 **⑤ 方案库待审**，运营师评审并「确认采纳」后才进 **① 全年计划池**。

**Q：拒绝的飞书规划还会回来吗？**  
A：重新同步时，已拒绝项不会回到待审列表（记录仍保留）。

**Q：送 Agent2 和确认采纳是一回事吗？**  
A：不是。先 **G2 确认采纳** 进全年计划池，再 **G3 主动送 Agent2**，两步分开。

**Q：②③④ 和 ① 是什么关系？**  
A：②③④ 是 ① 里已采纳活动，按**时间紧迫度 + 执行阶段**自动分流展示；同一时刻只在一个池。
